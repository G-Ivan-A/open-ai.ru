# Витрина BCREQ (mango) на open-ai.ru

Витрина промптов и стандартов для подготовки спецификации бизнес-требований (BCREQ)
публикуется в изолированном разделе сайта: <https://g-ivan-a.github.io/open-ai.ru/mango/>.
Описание и версия — <https://g-ivan-a.github.io/open-ai.ru/projects/mango-bcreq/>.

Мастер витрины — приватный репозиторий-спица `G-Ivan-A/mango_ba_prompts`: тексты промптов,
стандарты и сама витрина (`site/`) редактируются только там. open-ai.ru — хостинг уже
собранной витрины: workflow [`pages.yml`](../../.github/workflows/pages.yml) забирает
`site/` по токену только для чтения на зафиксированном коммите, ручного копирования нет.

## Источник: `source.json`

| Поле | Значение |
| --- | --- |
| `repository` | репозиторий спицы |
| `commit` | полный SHA коммита (не ветка и не тег): публикуется ровно он (НФТ-5) |
| `path` | каталог витрины в спице (`site`) |
| `version` | версия сборки витрины; должна совпасть с версией в `site/index.html` |
| `tree` | отпечаток `site/` на этом коммите: SHA-256 по путям и содержимому всех файлов и их число |
| `scenarios` | Playwright-сценарии спицы (`experiments/issue_500`) и коммиты срезов «до», на которых они написаны |

## Как витрина попадает на сайт

1. **Доступ** (`scripts/check-access.mjs`, ГК-2). Секрет `MANGO_SITE_TOKEN` проверяется
   запросами к GitHub API: закреплённый коммит и каталог `site/` на нём. Секрет не задан,
   токен отозван или истёк (401), нет прав или нужна SSO-авторизация (403), репозиторий не
   виден токену (404), коммит не найден (422), сеть недоступна — сборка останавливается с
   аннотацией `::error` и причиной. Токен не печатается ни при каком исходе.
2. **Загрузка.** `actions/checkout` спицы на коммите из `source.json` (sparse: `site/` и
   каталог сценариев) в `.spoke/` — вне публикуемого `_site`, без сохранения учётных данных.
3. **Подготовка** (`scripts/prepare-site.mjs`). Отпечаток `site/` и версия сверяются с
   `source.json`; любое расхождение — отказ (пустая или чужая витрина не выкладывается).
   Затем `site/` копируется в `_site/mango/` без изменений, кроме детерминированных правок,
   каждая из которых проверяет, что шаблон найден ровно ожидаемое число раз:
   - `gate.js`: `HOME_URL` — каталог витрины `/mango/` (в спице — адрес её собственного Pages);
   - `?v=<коммит>` у локальных скриптов, стилей, значка и у `data/*.json` в `app.js` (ГК-3);
   - подвал: коммит спицы рядом с версией сборки и ссылка «Все проекты» на стартовую страницу;
   - `deploy.json` — репозиторий, коммит, версия и отпечаток источника.
4. **Приватность** (`scripts/check-privacy.mjs`, НФТ-4): в публикуемых файлах нет токенов и
   учётных данных, ничего не загружается (скрипты, стили, изображения, `fetch`, `import`) из
   приватной спицы, `raw.githubusercontent.com` и с Pages спицы. Ссылки `<a href>` на документы
   спицы (CHANGELOG, «Источник» у шагов) — навигация для сопровождающих, они допускаются.
5. **Проверки в браузере** (Chrome через `playwright-core`):
   - `scripts/check-mango.mjs` — один и тот же прогон на эталоне (исходный `site/` спицы) и на
     развёрнутой витрине под base path сайта, результаты сравниваются целиком: карточки
     каталога и текст каждого «Копировать» из буфера обмена, поиск, фильтры, все шаги
     Ш-0 → AIN-01…24 → Ш-3…Ш-В в обоих форматах с текстом «Копировать» шага, разделы SPA,
     404 и ошибки JavaScript. Только для развёрнутой: версия и коммит в подвале, вход со
     стартовой и выход «Все проекты», заход вглубь (`/mango/ain-06`) и перезагрузка;
   - `scripts/run-spoke-scenarios.mjs` — `browser-smoke.js` и `route-browser.js` спицы на её
     коммите выполняются как есть; отличается только база URL. Исход на развёрнутой витрине
     должен совпасть с исходом на исходном `site/` спицы.

## Адреса

| Адрес | Что открывается |
| --- | --- |
| `/mango/` | витрина (каталог) |
| `/mango/#processes?step=AIN-06` | шаг процесса (адреса самой витрины, без изменений) |
| `/mango/ain-06`, `/mango/ш-3`, `/mango/sh-v?track=system` | `404.html` сайта переадресует на `/mango/#processes?step=…` (шаги — из `data/*.json` собранной витрины) |
| `/mango/catalog`, `/mango/glossary`, … | раздел SPA: `/mango/#catalog` |
| `/projects/mango-bcreq/` | страница «О витрине»: версия, коммит, отпечаток, ссылки на источник |
| `/mango/deploy.json` | паспорт публикации |

Внутренние ссылки витрины не выходят из `/mango/` (кроме «Все проекты»), брошюра не ссылается
внутрь витрины — это проверяет `scripts/check-site.mjs` в корне.

## Кэш и смена версии (ГК-3)

GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`. Чтобы после смены версии браузер не
смешивал новую страницу со старыми скриптами и данными, все локальные ресурсы и `data/*.json`
запрашиваются с `?v=<короткий SHA коммита спицы>` — у новой версии другие адреса ресурсов.
`index.html` без параметра: не дольше 10 минут после публикации (обычная перезагрузка — сразу
с проверкой `ETag`). Ресурсы стартовой страницы и брошюры несут `?v=<хэш содержимого>`.

## Переход на новую версию спицы

```sh
# site/ спицы на новом коммите — в отдельный пустой каталог
git -C <клон спицы> archive <sha> site | tar -x -C /tmp/mango-new
node projects/mango-bcreq/scripts/lock.mjs --update /tmp/mango-new/site --commit <sha> --version <x.y.z>
npm run build -- --mango-source /tmp/mango-new/site --base-path /open-ai.ru/
npm run check -- --site _site --base /open-ai.ru/
node scripts/check-mango.mjs --site _site --reference /tmp/mango-new/site
```

Изменение `source.json` проходит pull request; после слияния workflow публикует новую версию и
проверяет, что опубликованный `mango/deploy.json` содержит новые версию и коммит.

## Тестовая витрина

`tests/fixture/` — публичная мини-витрина с тем же устройством (`gate.js` с `HOME_URL`, разделы
`section[data-page]`, каталог с «Копировать», поиск, фильтры, шаги Ш-0, AIN-01…, Ш-В, подвал с
версией) и свой `source.json`. На ней pull request без доступа к секрету (например, из форка)
проходит ту же сборку и те же проверки, включая браузерные; публикации при этом нет.

## Структура

```text
projects/mango-bcreq/
  README.md            # этот файл
  source.json          # зафиксированный источник витрины
  page/index.html      # шаблон страницы «О витрине» (/projects/mango-bcreq/)
  scripts/
    check-access.mjs   # проверка токена до сборки (ГК-2)
    lock.mjs           # чтение и обновление source.json, поля для workflow
    prepare-site.mjs   # site/ → _site/mango/ со сверкой и правками
    check-privacy.mjs  # приватность публикуемых файлов (НФТ-4)
    tree.mjs           # отпечаток каталога
  tests/fixture/       # публичная тестовая витрина
```

Тесты — в `tests/` в корне репозитория (`npm test`).
